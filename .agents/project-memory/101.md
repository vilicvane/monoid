# SSH signing through WalletConnect

2026-10-29, first implementation; no card protocol changes.

The user chose Node.js + TypeScript for the sibling `monoid-ssh-agent`, public keys directly in WalletConnect accounts, and the existing Session → Switch flow. Namespace `monoid`, chain `monoid:ssh`, signature method `monoid_sshSign` and event `accountsChanged`; the later approved display metadata adds `monoid_sshGetKeyMetadata` and `monoid_sshKeyMetadataChanged`. Accounts encode Ed25519 public bytes or compressed P-256 SEC1 public bytes. SSH signing always binds the exact public key and original payload.

The App's `SSHKeyStore` is a stateless adapter over the current Safe, not a second persisted key directory. Safe imports native Ed25519/P-256 public keys, and Seed derivation stores generic public keys and exact parameters. Do not use the card identity key. `signSSHData` reads the actual public key through the same reference used to sign, uses pure Ed25519 over the complete data or exactly one SHA-256 before P-256 digest signing, and verifies the resulting SSH signature. Existing Applet CBOR size enforcement remains in force.

`SSHWalletService` maintains desired/acknowledged authorization independently of optimistic WalletKit state. Removing and re-adding an account cannot revive an old request. Persist `(topic,id,digest)` before showing an approval; persist terminal state before handing a response to SDK; restored pending requests never repeat a card operation. Keep records through the WalletConnect expiry, independently of the shorter business deadline. One SSH approval/card operation is active across sessions; additional requests return Busy. Signing checks current request, permissions and deadline before and after NFC and before publishing. State write failure prevents further signing.

The shared `@monoid/ssh-protocol` source is in the sibling agent repository. This App consumes `vendor/monoid-ssh-protocol-0.1.0.tgz` so independent checkout/install works. Run `npm run update:ssh-protocol [-- PATH_TO_AGENT]` to build/pack/install it, and retain the tarball and both package files together. The `.gitignore` exception is required.

SDK 2.25.0 updates session storage before ACK, and a failed ACK can suppress the event; code must reread current state.
