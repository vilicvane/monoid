# iOS 核心取舍与真机确认

- **NFC 交互**：Core NFC 有系统面板和会话时限。读卡前解锁已保存的 Access PIN，结束读卡后才输入 PIN 或保存凭据；错误时关闭系统面板，由用户重新发起。退出前台也终止当前扫描，超时或回到前台不自动重放安装、修改 PIN 或签名操作。AID 白名单需同时包含当前 applet bundle 的完整 AID、日常 SELECT 使用的版本无关前缀 `F06D6F6E6F69640201` 和两个 GlobalPlatform 管理器；只有完整 AID 会导致贴卡后首次显式 SELECT 被 Core NFC 以权限错误拒绝。固件升级改变 AID 时要同步更新。
- **移卡识别**：真机移卡可能返回 `NFCError 102` 而非明确的连接丢失。仅在 APDU 传输中、卡片已不可用且 reader 仍 ready 时，将响应/重试错误 `101/102` 归为 `TAG_LOST`，不弹应用错误层；系统面板应以 `Card connection lost.` 错误提示结束，避免显示成功勾号。正常读完后等待移卡仍算成功。其他通信错误仍报告，已发送 APDU 的结果仍为 `unknown`，不自动重试。
- **凭据保护**：每个显式 scope 一次 Face ID/Touch ID，最长 60 秒，后台或锁屏撤销；凭据限本机并绑定当前生物识别集合。接受 Keychain 将失效项表现为不存在、卸载后可能残留的边界；继续支持手动输入 PIN，不降低保护等级来规避失败。
- **相机首次授权**：真机上授权回调可早于弹窗的失活通知，回调时 App 与 scene 甚至仍同时报告活跃。首次请求必须等授权结果和请求开始后的 App 激活通知都到达，再确认 App 与所属 scene 同时活跃；已决定的权限不额外等待通知，无后置相机直接报 `NO_CAMERA`。真正退出活跃状态仍终止扫描。
- **二维码前台恢复**：主扫码页和 Bitcoin 扫码弹窗在返回前台后自动创建新会话，等待旧相机成功清理；已关闭、已接受结果及权限/硬件错误不自动重试。恢复时保持完整预览框，首帧就绪后仅淡出遮罩，首次进入才缩放。Bitcoin 弹窗通过外部点击或返回关闭，无 Cancel 按钮；加载圈仅用于主扫码页处理链接。真机已验证两处连续两次切出返回、关闭后不重开，以及首次授权正常。
- **系统读卡进度**：公开 Core NFC 接口没有控制系统转圈动画的开关，可在有效会话中更新 `alertMessage`。扫描提示宿主读取已渲染的真实阶段和计数文本，经 `setSessionMessage` 同步到当前连接；原生校验 session ID、连接及结束状态，过期更新不能覆盖移卡/断卡提示。不额外发送 APDU、不重试或延长操作。依据：[Apple reader session API](https://developer.apple.com/documentation/corenfc/nfcreadersessionprotocol)。
- **刷卡音效**：用户确认与 iOS 系统刷卡提示一致，遵循静音开关。Capacitor 的内置 WAV 在真机返回 `status=0, type=basic`，读取时需接受这种非 HTTP 响应；不能仅看 `response.ok`，仍需拒绝 opaque/error 响应和 HTTP 错误。修复后用户已确认有声，无需改用原生播放器或切换音频类别。
- **真机验证**：已完成签名安装，用户确认基本 NFC 读卡、刷卡音效，以及读取中移卡后不弹应用错误层、系统面板显示断卡提示均正常；`MonoidUITests` 已在真机验证仅重置 Monoid 相机权限后，首次允许即可进入并保持预览，无需切换页面。卡片安装/写入/签名、系统取消/超时、相机旋转裁切、生物识别集合变更仍需继续验证。模拟器无法证明射频通信或 Secure Enclave 行为；尤其 GlobalPlatform 管理器 `A000000003000000` 的实际 Core NFC 接受情况需要实卡确认。
