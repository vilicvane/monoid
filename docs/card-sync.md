# 多卡同步与复制

更新日期：2026-10-26。

Safe → Card 中的 Sync 和 Copy 传递卡片上实际存在的条目，不自动导入手机，也不把手机尚未上传的 Alias 或地址变动加入结果。手机与单卡之间的下载合并、上传替换仍遵循[地址管理规则](address-management.md)。

## 不透明条目

Sync、Copy 和恢复导出不验证功能内容。所有条目都按 index、type、metadata、alias、Secret 标记及可读取的正文处理；不以 OTP、Security Key 等功能解码结果决定是否参与，也不迁移旧格式。

因此，旧的两项式 OTP（公共 `0xf201` 记录及其 `0x05LL` HMAC 项）、缺少 scope 或无法解码的 `0xf101` 凭证都原样传递。旧 OTP 的 metadata 不被解释成新的关联类型。各功能页和 Card 行仍按自身格式逐项解码，跳过无法显示的记录。

只有钱包派生清单 `0x0f01` 保留既有的 wallet-list 合并规则。这是合并规则，不是参与条件：无法解码或关联不匹配的记录按原始字节使用通用规则。

## 同步范围

一次 Sync 可以包含不同 Bundle 的卡和未加入 Bundle 的卡，不改变 Bundle，不重置、安装或更新 Applet。合并身份为 `scope + index`。

| 条目                             | 参与范围               | 读取和传递                                 |
| -------------------------------- | ---------------------- | ------------------------------------------ |
| 普通非 Secret 条目，包括公共凭证 | 所有参与卡             | 读取正文，原样补齐                         |
| Bundle 内的 Secret               | 相同 Bundle 的卡       | 卡端加密 Export/Import，不读取 Secret 明文 |
| 未加入 Bundle 的 Secret          | 仅原卡                 | 不跨卡传递                                 |
| 可解码且主资源存在的派生清单     | 与主资源相同的范围     | 合并钱包列表，不扩大主资源范围             |
| 无法解码或主资源缺失的派生记录   | 按记录自身 Secret 标记 | 原样传递                                   |

当前单项 OTP 账户自身是 Secret，按自身 Bundle 范围传递。旧式公共 OTP 记录和 HMAC 项分别按自身 Secret 标记传递。公共 Security Key 凭证不自动携带本地 Seed。

Copy 保留原协议边界：Bundle 来源只能复制到同 Bundle；未加入 Bundle 的来源使用目标完整公钥生成加密包。多目标共享 Bundle 包，非 Bundle 包分别绑定目标。

每次刷卡核对完整 Card ID、公钥和 Bundle。身份或 Bundle 改变后需要重新读取。不能只凭显示的短 ID 判断卡片。

## 合并规则

同一范围、同一 index：

1. type、metadata、Secret 标记及可读取正文相同，无需写入。
2. 仅 Alias 不同：Sync 取添加顺序中的首个非空值；Copy 保留目标已有 Alias。空 Alias 不作为清空其他卡名字的命令。
3. 两边均为有效钱包派生清单：通过 `card-derivations.ts` 取钱包列表并集。
4. 其他任何内容差异：只报告这一项冲突，不覆盖已有内容，不先删除再重建。

Secret 正文不能读取时只比较可观察字段，不比较随机加密信封，不调用功能解码器或 ViewKey。不同范围的同 index 不能借覆盖改变 Secret 属性或范围。

从 Card 进入的卡为第一张；后续卡按成功加入顺序排列。重新扫描和写入顺序不改变 Alias 优先级。收集完成后固定卡片和计划，再开始写入。

资源集合与可合并的钱包清单取并集，不传播删除。已记录的空清单不同于从未创建清单；全部为空时保留空记录，另有非空记录时取并集。不会生成默认派生地址，也不会将公钥缓存、手机 default 或预览状态写入清单。钱包身份仍为源 Key index、address type 和完整派生参数。

不同 index 分别保留，不按 RP、用户、账户名称或凭证 scope 去重，不推断哪条更新或有效。Copy/Sync 不迁移 Applet grant，不自动授权、切换 Seed 或修改 domain；公共凭证存在不等于目标卡具备使用它所需的 Seed、domain 和本卡授权。

## 执行、单项结果与中断

收集和写入前输入 Secret PIN，每次刷卡重新认证；PIN 不持久化。Card 页的列表快照不等于已读取 Sync 所需的正文和导出包。

读取失败、单项冲突或目标明确拒绝（例如旧格式 `0xf201` 被新固件以 `INVALID_PARAMETER` 拒绝）都记为该项结果，其余项继续。详情显示 index 和原因；处理结束后仍能查看，不以完成动画隐藏失败。被跳过的条目不计作成功写入，也不自动重试。

NFC、PIN／权限错误、取消及结果不确定的写入仍停止操作，取消保持安静。不回滚已确认的项目。每个成功响应先更新会话状态，再检查取消或发出下一条命令。

用户显式继续时，只读取响应丢失的项目来核对结果；已成功的写入不重放。只有明确读到原状态或条目不存在才继续未完成写入。单项 `EXISTS` 使用 package 2 的 `acceptMatchingItem` 检查实际条目，不当作无条件成功。缺失项删除仍按原规则跳过。

正常写入直接执行固定计划，不在前后全量复读。参与卡片由当前流程独占修改，不额外检测其他设备的并发变更。计划结果不能提前当作卡上事实，后续失败不能隐藏已确认的写入。

无变化的卡不需要再次刷卡。至少两张卡均无需同步时，使用普通返回按钮替代 Continue，不进入 Complete，仍可添加、移除或重新读取。从 Card 进入时优先 Back to Card，否则 Back to Safe；独立入口返回 Safe。已处理的卡再次刷入时，只核对身份及 Bundle，不再认证或写入。

卡片写入自动使 CardStore 缓存失效。原 Card 页需要预览时，复用已确认的条目及已知公钥，仅补读缺失的地址预览；预览失败不把未读地址当作空清单。手机已导入的 Key、钱包、Alias 和默认选择不受 Sync 改动。

普通 Copy/Sync 只保留本次内存会话，不构成跨重启恢复档。

## 重装前的完整恢复档

替换 Monoid 存储的 Bundle 更新或重装使用 Sync 合并，但把待更新卡 A 的写入延后至安装后。只更新其他 Applet 而不替换 Monoid 存储时不需要此流程。Fresh install 更换 Identity，仍使用独立安装流程。

1. 读取 A 的所有条目和原授权范围，将 A 作为第一张卡加入同步。
2. 添加同 Bundle 的其他卡，处理所有 peer 的同步计划。A 的写回留到安装后。
3. 从已处理的 peer 重新导出完整合并结果。先确认它包含 A 的每个条目及内容；若冲突或拒绝导致缺失，错误指出 index，禁止重装。不能因“部分同步已结束”就声称恢复完整。
4. 对来源卡的每一项重新 Export，避免使用 A 签发的旧缓存包。任何一项真正无法导出都是硬停止，不返回部分恢复档；错误指出该项。没有功能格式过滤，也没有旧的 skippedIndexes 阻断。
5. 校验来源身份、Bundle、包头、元数据和导入大小，持久化完整档案并读回核验后，返回 Card Applets。用户明确继续安装，才执行破坏性替换。
6. 安装后逐项导入全部档案。目标拒绝某项或已有项冲突时报告 index 和原因，继续其余项目。完整恢复档与授权材料保留至全部恢复成功，不把部分恢复当作全部完成。
7. 条目恢复完整后核验资源，一次性检查授权依赖的 Seed／Key 和目标 Applet，再恢复 A 原授权范围；不复制 peer 的 grant 或安装 token。

准备失败不会触发重装。导出中断可显式重试或选择另一张已处理的 peer，仍必须得到完整档案。完整档案保存后可退出或重启，在 Card Applets 继续恢复。已经重装但尚未恢复的 Bundle 卡可从另一成员准备恢复档，只恢复数据和授权，不再次重装。

准备同步中的 Start over 返回 Card Applets，已写入 peer 的内容不回滚。仅 ready 且无替换检查点时允许丢弃准备档；替换开始后保留恢复材料，使用 Resume 操作。准备完成仍显示 Continue installation／Continue update，并保留原确认流程。

协议仅使用 `metadata`／`metadataPrefix`；维护档案的既有落盘字段映射独立保留，不改写旧条目正文或加密包。

## 验收与验证边界

- 旧两项式 OTP、无法解码的 Security Key 凭证及损坏派生记录原样通过 Copy、Sync 和恢复导出。
- 同 index 的一项冲突与一项目标拒绝均独立报告，其余条目完成；现有数据不被覆盖。
- 有效派生清单取并集，Alias 保留原优先级，Secret 不跨未授权范围。
- 掉卡、取消、PIN 错误和未知写入结果停止；显式继续先核对，不重放已完成写入。
- peer 缺少 A 的任一项或任一 Export 失败时，不允许持久化不完整恢复档或开始重装。
- 恢复导入拒绝一项时，其余项完成，原档案保留，不能提前恢复依赖不完整条目的授权。

自动测试和模拟卡验证合并、逐项结果、范围隔离和中断状态，不能替代真实卡片的容量、加密传输、PIN、掉卡和多卡轮换验收。本次修改不宣称已完成实卡验证。
